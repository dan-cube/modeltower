# ModelTower 常见问题

[English](faq.en.md) · [操作指南](guide.zh-CN.md) · [回到首页](../README.zh-CN.md)

适用于 ModelTower 0.5.2。出问题时，先点窗口底部的**体检**。它逐项检查，每一项不过都会说原因。下面是体检之外最常被问到的。

## 打开、权限和更新

### 双击打不开，系统说无法验证开发者

正常。ModelTower 没有经过苹果公证，第一次要手动放行一次：

1. 先关掉系统的提示框。
2. 打开「系统设置 → 隐私与安全性」，滚到「安全性」，点 ModelTower 那一行旁边的**仍要打开**。
3. 输 Mac 密码或按指纹。

之后就能正常打开，更新到新版时可能要再放行一次。

### 系统问我允不允许访问「本地网络」

0.5 只用这一台 Mac，用不到，允不允许都行。以后在「系统设置 → 隐私与安全性 → 本地网络」里能改。

### 打开后窗口是空的，或者提示找不到 Python

打开后看到的是一页"先装 oMLX"，没有平时的主窗口：ModelTower 自己不带 Python，用的是 oMLX 自带的那一个。这台 Mac 上既没找到 oMLX，也没有别的 Python。两条路选一条：

1. **装 oMLX**（本来也要装）。点"打开 oMLX 下载页"，下载后把 oMLX 拖进"应用程序"，回到 ModelTower 点"重新检查"。
2. **装苹果的命令行工具**。点"装苹果的命令行工具"，系统会弹出安装框，装完（约几分钟）点"重新检查"。

哪条路都行。走了第 2 条，之后"开始使用"的第 1 步还是会带你装 oMLX。

### ModelTower 怎么更新

ModelTower 有新版时，「设置 → 更新」会提示，并给一个**下载页**的链接（本仓库的 [Releases](https://github.com/dan-cube/modeltower/releases)）。应用里不会自己下载、自己替换：

1. 按 ⌘Q 退出 ModelTower。
2. 到 Releases 下载新版的 zip，解压，把新的 ModelTower 拖进「应用程序」替换旧的。设置都在 `~/Library/Application Support/ModelTower/`，换应用不会丢。
3. 打开新版。系统要是又拦一次，照上面"无法验证开发者"那样放行。

提示要靠联网检查读到签了名的更新信息。关了联网检查、或者一时读不到，不影响使用，也可以自己到 Releases 看有没有新版。

## oMLX

### 控制台说这台还没装 oMLX，可我装了

控制台只对接两种装法：官方安装包装的 oMLX 应用，和用 Homebrew 装的。

- 用别的办法装的（比如自己从源码装）：控制台能看到它，但开关不了它，会提示你用它自己的方法启动和关闭。
- 刚装好：等几秒，控制台会自己接上，不用重启。
- 把 oMLX 拖进废纸篓又没重装：控制台按「没装」算，可以点**安装 oMLX…**重新装，装回来接着用原来的设置。

### 控制台说「这个 oMLX 不是官方签名的」

控制台核对过 oMLX 应用的签名，发现不是它的开发者签的，所以不对接。请删掉它，用**安装 oMLX…**从官方安装包重新装。

### oMLX 版本旁边写着「版本太旧」或「还没验证」

控制台带一份兼容表，记着哪些 oMLX 版本验证过；联网检查读到新的签名兼容表时会换上新的。版本旁边的话是照它判断的：

| 写的是 | 意思 | 怎么办 |
|---|---|---|
| 已验证 | 这一版完整测过 | 不用管 |
| 能用，有已知的不足 | 能用，旁边会写缺什么 | 看说明决定升不升 |
| 还在验证 | 正在测，目前没发现问题 | 可以用 |
| 比已验证的新，还没验证，一般能用 | 你的 oMLX 比控制台测过的还新 | 可以用，遇到怪事先怀疑它 |
| 兼容表里没有这一版，还没验证 | 控制台不认识这一版 | 同上 |
| 版本太旧 | 低于最低要求（0.5 要 oMLX 0.8.0 起） | 到「设置 → 更新」点**升级…** |
| 这一版有已知问题 | 这一版被标了问题 | 按旁边的说明换一版 |

装的是 oMLX 的测试版（比如 0.8.0rc1）时，「设置 → 更新」写「测试版，请升级到正式版」：正式版已经发布了，升到最新的正式版就好。

### oMLX 出了新版，控制台还没提示升级

控制台先核对新版，核对过了才提示，所以会比 oMLX 发版晚一点。核对完会发一份新的签名兼容表，控制台的联网检查读到它，就会提示「可以升级到 ××」。

等不及也可以自己升级，版本旁边会写「比已验证的新，还没验证，一般能用」。

### 控制台为什么要读 oMLX 的主密钥？安全吗

oMLX 的管理功能（列出、加载和卸载模型，管理子密钥，看日志和多轮缓存）只认主密钥。控制台要替你做这些事，就得用它。

- 控制台**只记你允许还是不允许**，不存密钥，每次用时从 oMLX 自己的设置里现读。
- 不允许也能用：能看状态，但看不到这台有哪些模型，不能加载和卸载。
- 随时能改：「设置 → oMLX」里点**允许…**或**改成不允许**。
- 主密钥不会发给客户端，也不会传到别处。

### 「入口」是什么，能关吗

入口是客户端和 oMLX 之间的一道门，每次请求多约 1 毫秒。

官方 oMLX 的子密钥有个特点：客户端点一个没加载的模型，oMLX 会直接把它加载起来。几个客户端各点一个，内存就满了。入口挡住这件事：它只放行已经加载的模型，加载、卸载和管理页都不让客户端碰。子密钥的「停用」也是入口做的。

能关，在「设置 → oMLX」里。关了以后客户端要改连 oMLX 自己的端口，没加载的模型会被点起来，停用的子密钥也能用了。

### 入口没在运行，说端口被别的程序占着

入口默认用 8900 端口，oMLX 默认用 8000。别的程序占了其中一个，就会起不来。

- 「设置 → oMLX」的入口一行会写是哪个程序占着。退出那个程序，再点**现在启动**。
- 点底部的**体检**，端口的问题会单独列一项。

## 下载

### 下载 oMLX 安装包很慢，或者下不动

- 在中国：到「设置 → 更新 → 下载源」选「中国」（只走魔搭转存），或者「自动」（两边测速，挑快的）。
- 还是不行：安装窗口里有**打开发布页**，用浏览器手动下好（GitHub、魔搭转存都行），再点**我已经下载好了 → 选择安装包…**。
- 下载中断：再点一次**下载**，会接着下，不用从头来。

### 下载 oMLX 安装包后说核对不上

控制台已经把文件删了：它和兼容表里记的 SHA-256 不一样，可能下坏了，也可能被改过。换个下载源再试（安装窗口里的「来源」）。

自己从别处下的：点**我已经下载好了 → 选择安装包…**，控制台会核对，告诉你这个文件是哪一版、能不能用。

### 魔搭转存是官方的吗？安全吗

不是 oMLX 官方的，是本项目在魔搭上放的一份原样转存，和 oMLX 项目没有关系。地址：<https://www.modelscope.cn/models/skyeyes1999/omlx-release-copy>

- 里面是 oMLX 官方安装包，一个字节都不改，附 oMLX 的 LICENSE 和 `SHA256SUMS`。
- 控制台不管从哪下，都按兼容表里的 SHA-256 核对，一个字节不一样就不装。所以多一个来源不会多一份风险。

详见[操作指南第 8 节](guide.zh-CN.md#中国区下载魔搭转存)。

### 模型下载很慢

模型是在 oMLX 的管理页里下载的，下载源由 oMLX 决定。

- 在中国：在 oMLX 的模型下载页里选「魔搭」，这是官方 oMLX 自带的，一般最快。
- 「设置 → 更新」里把下载源选成「中国」，「开始使用」会提醒你这一步。
- 魔搭上没有的模型：同一页勾上「也把 oMLX 的 Hugging Face 地址换成社区镜像」。注意那是个人维护的社区镜像，没有官方保障；下完可以取消勾选。

## 模型

### 我的模型放在别的文件夹，控制台看不到

点「开始使用」第 2 步里的**添加已有的模型文件夹…**（「设置 → oMLX」的「模型文件夹」一节也有），在访达里选那个文件夹。

- 只是给 oMLX 多加一个模型文件夹：oMLX 自己下载模型的地方不变，控制台和 oMLX 都不往你选的文件夹里写东西。
- 有模型在线时会先问你：oMLX 改模型文件夹会卸载已经加载的模型。
- 模型要是 oMLX 认得的格式（MLX 格式）。

### 模型加载不了，或者按钮写着「切换」

- 写「切换」：这台的内存放不下两个模型一起跑。点了会先卸载别的，再加载这一个。
- 加载失败：点**操作记录**看原因。最常见的是内存不够。照「开始使用」第 2 步建议的大小挑模型，第 3 步的下拉框里标着「· 放不下」的别选。
- 卡在「加载中…」很久：顶部出现「可能卡住了」时，点**现在再查一次**；还不行，重启这台的 oMLX（机器卡片上的**重启**）。

### 顶部一直提示「内存超线」

对话塞满上下文时，整台用的内存可能超过安全线（总内存的 90%）。提醒里会写原因和改法，任选其一：

- 把模型的上下文调小：提醒旁边有「改成 512K」这样的按钮，点一下就改好；
- 打开模型卡片上的「表放 SSD」（有这个开关的模型）；
- 卸载一个模型；
- 关掉占内存的别的程序。

### oMLX 管理页里「显存上限」那一行是红的

可以不管。控制台的安全线是总内存的 90%，本来就低于系统默认的显存上限，按控制台的提醒用就不会碰到它。

### 上下文默认为什么是 256K

你在 oMLX 里给这个模型单独设过上下文，控制台就用你设的；没设过就默认 256K，模型本身最多不到 256K 的用它的上限。不一上来就用模型的最大值，是因为上下文越长，塞满时占的内存越多。想要更长，在模型卡片上改。

## 客户端

### 客户端连不上，或者说模型不存在

按顺序查：

1. 模型卡片是不是写着「在线」。入口只放行已加载的模型；「连接客户端」页上灰着写「加载后可用」的，要先加载。
2. 地址是不是照「密钥 → 连接客户端」页上的填的。大多数客户端要带 `/v1` 的地址（点**复制**）；Chatbox、Cherry Studio 这类要不带 `/v1` 的（点**复制根地址**）。
3. 模型名是不是那一页列出来的。
4. 密钥是不是子密钥，有没有被停用或删除（同一页里看）。
5. 客户端是不是装在这台 Mac 上。这个地址只在本机能用。

### 网页版、Electron 做的客户端能连吗

能。入口会放行浏览器发的预检请求，所以在这台 Mac 的浏览器里打开的网页版客户端、Electron 做的桌面客户端都能连上；真正的请求照样要子密钥。

### 别的电脑、手机能用这台的模型吗

0.6 起支持。0.5 里客户端的地址只在本机能用。人在外面的时候，0.6 会支持借 Tailscale、蒲公英、EasyTier 这类组网软件连回来。

### 能不能把几台 Mac 连起来一起用

联机在 1.0 推出：几台 Mac 在一个窗口里一起管，每台加载不同的模型；配对时核对指纹和核对码，不经手对方的密码；能随时吊销，也能选给多大的权限。0.5 里「添加机器」「本机授权」点进去是预告页。

## 卸载

### 怎么完全卸载

基本步骤见[操作指南第 10 节](guide.zh-CN.md#10-卸载)。下面是 ModelTower 留在应用之外的全部东西：

| 在哪 | 是什么 | 怎么清 |
|---|---|---|
| `~/Library/Application Support/ModelTower/` | 控制台的设置、下载的 oMLX 安装包、日志、入口的设置 | 整个文件夹删掉 |
| `~/Library/Preferences/io.github.dan-cube.modeltower.plist` | 应用偏好（比如窗口是否固定） | 删掉这个文件 |
| 「系统设置 → 通用 → 登录项」 | 打开过「登录 Mac 时打开控制台」才有 | 卸之前在「设置 → 通用」里关掉；已经卸了的话，在登录项里删掉 |
| oMLX 的设置里 | 你让控制台替你写进去的：子密钥、各模型的上下文和开关、多轮缓存的上限、加的模型文件夹；关过 oMLX 的自动更新、勾过 Hugging Face 社区镜像的话还有这两项 | 卸之前在控制台里点**还原**（自动更新）、**还原 Hugging Face 地址**；子密钥、上下文、模型文件夹到 oMLX 的管理页里删或改。已经卸了的话，都到 oMLX 的管理页里改 |

ModelTower 不往系统里装常驻的后台服务。oMLX、它的设置和模型文件不属于 ModelTower，卸 ModelTower 不会动到它们。

## 还是解决不了

「设置 → 关于」里有本项目的 GitHub 地址，到仓库的 Issues 里说明：你点了什么、看到了什么、**体检**和**操作记录**里写了什么。贴内容前请先把密钥删掉。
